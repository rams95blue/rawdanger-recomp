# Roadmap (native port, ps2-native-recomp)

The game runs natively through our fork of ps2-native-recomp (`engine\ps2-native-recomp`, see `engine\FORK.md`), built
by `RawDangerPC.exe`. US, JP and both JP demos build and play. The old ps2recomp roadmap is kept in
`ROADMAP_ps2recomp.md` for its research (scene table, overlays, memory card, FMV notes).

Everything new goes into **Raw Danger! Enhanced Edition** (`games\RawDanger-Enhanced`), built from the US disc once all
five discs are present (US, EU, JP and the two JP demos), because several items below take their data from them. The plain US/JP builds stay as
close to the console as possible.

Status: ✅ done and verified · 🔧 in progress · 🔬 researched, not built · ⬜ not started

## Milestone 2b - the demos

US/JP builds of both JP demos (Type-A, Type-B) work. Compared with the retail programs (`docs\DEMOS.md`, re-run with
`rd.py demos`): Type-A is an early build (20-byte scene entries, 27 scenes, only the opening building's 4 maps); Type-B is
close to retail (35 scenes, 28 maps) but lacks the post-game extras (Showcase, Radio, Memories, Compass, episode
save/load). Type-B's program names three maps the retail game does not have: **M3_10_01, M3_12_00, M4_01_00** (no data
under those names on the retail discs). Whether the Type-B disc carries them is the next check (`rd.py demos` reads its
ROOT.FAT); if it does, they are candidates for the Enhanced Edition.

## How each item is checked

Code patches go into `patches\pnach\SLUS-21501_2905C5C6.pnach` as named sections (the launcher picks them by name) and are
compiled in at build time (the native engine ignores runtime writes to code). Each one is verified on a headless build
of the same engine: boot or a save state, frames captured every N frames, compared with the unpatched build.

## Engine pipeline

The game is not decompiled: its machine code is translated to C++ mechanically (eerecomp), function by function, so it runs natively but reads like the machine code it came from. What is understood is mapped by hand (docs/CAMERA.md, DEBUG.md, NATIVE_RENDERER.md) and changed in two ways: words written into the program before it is translated (the pnach sections), and since v0.9.0 calls into the engine's own C++ from the game (host calls), for logic too big for a few words.

Worth improving, by what it would bring:

1. **Code changes without a new build.** A changed word in already-translated code is not seen (a patch line writing the orbit call had no effect until the program was translated again: 5 minutes here, longer on a slower PC). If the engine re-translated a function when a patch changes its code (it does already for code the game loads itself, ee-live), the camera and debug features could ship as patch files with no rebuild.
2. ~~**A missing host call stops the game**~~ (v0.9.2: the engine carries Raw Danger's own settings for its two calls) ("missing code at 0x0FF00320") when the program has the call but the engine was started without its setting (an older launcher): the engine could carry, for each host call, the instructions it stands in for, and do just those.
3. **Hand-written functions**: replacing a whole game function with C++ (the camera, the head's look-at, the debug menu) instead of a few patched words; host calls are the first step.
4. **A symbol map** of the functions found so far (tools/rd_symbols.txt) used by the tools and the notes.
5. **Uncapped frame rate** needs the native renderer's in-between frames (pending 9, 12).
